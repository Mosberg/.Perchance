Heads up! This is a fork/remix of the upload-plugin, but unfortunately it's a really bad idea to fork this plugin, since its code is 'coupled' with the server code, so if I need to change the server code, your version of this plugin will likely break. If you'd like new features, best to ask for them on the community forum so your generators don't randomly break in the future when I update the server code. Alternatively, you can create a new plugin that imports this plugin - i.e. basically create a "wrapper" plugin that changes/expands on this plugin's behavior

Upload Plugin

Important: When uploading files that are only needed temporaily, use the expires option to get up to 400x higher file size and daily upload limits. See the "Temporary Files" section below for info.

This plugin allows you to 'programatically' upload data to Perchance's file storage server - like perchance.org/upload, except via code instead of a drag-and-drop interface.

So, for example, you could make a generator where the user can click a button to save their generated result, and get a URL for it. The user doesn't need to be logged in to Perchance to trigger the upload, but the file size allowance for this plugin is smaller than perchance.org/upload.

Note: For now, this plugin is mainly for people who know how to use functions/JavaScript. It's probably not that useful for "regular" Perchance generators, but might be handy if you're building something a bit more complex. For example, it's used in perchance.org/ai-chat to allow users to create a character and then share their character via a URL.

To use this plugin, you'll first need to import it by adding this line to your lists editor: 

upload = \{import:upload-plugin\}

And then you can use it inside functions like this:

async saveSomeText() =>  // <-- add 'async' before the function name since we need to use 'await' in this function
  let \{ url \} = await upload("this text will be uploaded as a text file");
  outputEl.innerHTML = url;

Here's an example generator to start you off, and here's and example that shows how to compress data before uploading (and then decompress when downloading) which can allow you to fit up to ~10x more data within the upload limit.

You can give a string or a Blob to the upload function, and it will return an object with url, size, and error properties. The error value will be null unless there was actually an error. The size value is in bytes. 

let \{ url, size, error \} = await upload("...");

If an error occurred during upload, then error will be a string like "over_daily_allowance" or "file_too_big" or "invalid_filetype".

Editable Text Files

Editable files have one stable public URL whose text can be replaced. File names are chosen entirely by your code. Anyone who knows or guesses the name can read the file, so choose a long random name when you want the URL to be difficult to discover. 

let created = await upload.editable.set("profile-4mtq8jpn2v6xkycqzr5lhw", JSON.stringify(profile));
if(created.error) throw new Error(created.error);

// Save this somewhere private. It is returned only when the name is first created:
localStorage.profileEditKey = created.editKey;

let updated = await upload.editable.set(
  "profile-4mtq8jpn2v6xkycqzr5lhw",
  JSON.stringify(nextProfile),
  \{editKey: localStorage.profileEditKey\},
);

The plugin generates a random editKey when a name is first created. Future changes to that name require the key. It cannot be recovered, so save it if you need to edit the file later.

set accepts strings up to 5 MiB and requires a saved generator (including while editing one). Names are 1 to 200 characters using lowercase letters, numbers, and hyphens. A name can commit one changed value every 10 seconds. If several changes are queued for one name, only the latest pending value is kept and displaced calls resolve with superseded === true and error === null. Uploading identical text is a free no-op.

Each successful set also resolves with an editCount: it is 1 when the name is first created and increases by 1 for each committed change. Reads of the raw URL can be up to ~10 seconds stale after a write, so to immediately read your own write, append ?v= plus the returned editCount to the raw URL — each new value bypasses the stale cache entry.

Read the current text like this:

let text = await upload.editable.get("profile-4mtq8jpn2v6xkycqzr5lhw");

get returns null if the file does not exist. It throws for network errors and other unsuccessful HTTP responses. The corresponding raw URL is https://editable.uploads.dev/file/$\{generatorName\}/$\{name\} and is publicly fetchable from any generator.

Editable writes use the normal anonymous upload quota.

Temporary Files

If the uploaded file is only needed temporarily, then you should add an expires parameter with the specific time (in milliseconds) that you want the file to "expire".

The maximum file sizes and daily quotas are much higher for temporary files. The sooner the file expires, the larger the boost in allowed size/quota. For example, if you set the expires parameter to 24 hours or less, then the maximum file size and allowed daily quota are increased by 400x. And on the other extreme, if the expires parameter is 1 year, then you'll get a 20x boost to the limits.

Below is an example of uploading a text file with the content "abc", and setting the expiry time to 24 hours from now. We put "abc" as the first input to the function, and then after a comma we add an object with the expires parameter in it. 

let \{ url, size, error \} = await upload("abc", \{expires:Date.now()+1000*60*60*24\});

Date.now() gives us the current time in milliseconds, and we add 1000*60*60*24 to it, which is the number of milliseconds in 24 hours.

Note that the file is not guaranteed to be deleted after the expires time that you set. All that's guaranteed is that the file will last at least that long.

Manual Deletion

Files can be deleted within 3 days of upload. To delete an uploaded file using this plugin, make a request to the deletionUrl value that is returned by upload: 

// the 'deletionUrl' value is a URL which triggers deletion when a fetch request is made to it:
let \{ url, deletionUrl \} = await upload("...");
// the file has been uploaded

// then, later...

// make a request to the 'delete' URL to delete it:
let \{ success \} = await fetch(deletionUrl).then(r => r.json());
if (success) \{
  // the file is now deleted
\}

Moderation

If you want to allow users to upload files on your generator, but e.g. want a way to detect whether the file is nsfw (e.g. before displaying it on a page where everyone can see it), then you can use this: 

let \{ url, size, error \} = await upload("...");
let result = await fetch(`https://upload.perchance.org/api/fileInfo?url=$\{url\}`).then(r => r.json());
if(result && result.tags.includes("nsfw")) \{
  // do whatever
\}

You can also use the file ID like this: https://upload.perchance.org/api/fileInfo?id=$\{\}` 

let id = url.split("/").at(-1);
let result = await fetch(`https://upload.perchance.org/api/fileInfo?id=$\{id\}`).then(r => r.json());

See the deletion example for a simple demo of this.
