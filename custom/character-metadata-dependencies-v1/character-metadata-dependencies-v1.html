character-metadata-dependencies-v1 — JavaScript dependency guide

This document explains the third-party *.js files packaged or referenced by the character-metadata-dependencies-v1 plugin and how each library is typically used within the plugin.

Overview

The plugin build/packaging script concatenates several libraries into a single distributable bundle.js. The bundle contains the libraries listed below and is intended to provide a small set of proven client-side utilities used by character metadata generators (storage, Markdown parsing, sanitization, and DB export/import).

Files and purpose

  • bundle.js
    (concatenated bundle generated by the plugin's build script)
    • What it is: a single-file distribution that contains multiple upstream libraries concatenated in a fixed order for easy inclusion in Perchance generator pages.
    • Why use it: reduces HTTP requests and avoids runtime import issues inside isolated Perchance pages where bundlers are not available.
  • dexie.min.js
    (Dexie v4.x)
    • What it is: a lightweight, promise-based wrapper around IndexedDB that exposes a convenient API for creating databases, defining object stores, and running queries.
    • Typical uses in this plugin: cache generated character metadata, keep a local collection of user edits, store settings or small caches so subsequent page loads are faster and work offline-ish.
    • Simple usage example: 
      const db = new Dexie('CharacterDB');
db.version(1).stores(\{ characters: '++id,name,universe' \});
await db.characters.put(\{ name: 'Alice', universe: 'Example' \});
const rows = await db.characters.toArray();
  • dexie-export-import.min.js
    (dexie-export-import plugin)
    • What it is: a helper plugin that adds/export-import capabilities for Dexie/IndexedDB databases so the site can export DB contents to a JSON/Blob and later import them back.
    • Typical uses: provide "Export" and "Import" features so users can back up their generated character data, transfer it between browsers, or restore a previous snapshot.
    • Notes: the exact API surface depends on the bundled version; consult the library docs if you need advanced options (format, compression, blob vs JSON).
  • marked.min.js and marked.umd.min.js
    (Marked - Markdown parser; two builds are included for compatibility)
    • What it is: a fast Markdown parser that converts Markdown text to HTML (or tokens) in-browser.
    • Typical uses: parsing scraped character bios, wiki excerpts, or user-provided Markdown so the generator can either render a safe preview or extract clean text to feed into the AI prompt.
    • Why two files: one build may be a specific minified release and the other a UMD build; including both is a compatibility strategy so code can use whichever entrypoint is available in the runtime environment.
    • Simple usage example: 
      const markdown = '# Biography\nA short bio...';
const html = (typeof marked !== 'undefined') ? marked.parse(markdown) : ''; // or marked(markdown) in some builds
  • purify.min.js
    (DOMPurify v3.x)
    • What it is: a DOM sanitization library that removes or neutralizes potentially dangerous HTML (scripts, event handlers, XSS vectors).
    • Typical uses: always sanitize HTML produced from untrusted Markdown or scraped content before injecting it into the page. For example, run the HTML produced by Marked through DOMPurify prior to innerHTML insertion.
    • Simple usage example: 
      const dirty = 'Some bio';
const safe = DOMPurify.sanitize(dirty);
document.getElementById('preview').innerHTML = safe;

How these pieces are typically combined

  1. Fetch / scrape a character page (server or client).
  2. Extract a Markdown or HTML snippet and parse it with Marked to normalize formatting.
  3. Sanitize the resulting HTML with DOMPurify before rendering in the UI.
  4. Store the final character object in Dexie so it is available offline and can be indexed/queryable.
  5. Offer an export/import UI backed by dexie-export-import so users can backup/restore their DB.

Include / usage recommendations

If you are authoring a Perchance generator page, include the distributed bundle (recommended) or load libraries individually if you need a slimmer set of features: 

<!-- single-file bundle (recommended for plugin pages) -->
<script src=".schemas/plugins/character-metadata-dependencies-v1/bundle.js"></script>

<!-- OR load individual libraries from CDN when developing -->
<script src="https://cdn.jsdelivr.net/npm/dexie@4.4.3/dist/dexie.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/dexie-export-import@4.4.0/dist/dexie-export-import.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/marked@4.3.0/marked.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/dompurify@3.4.7/dist/purify.min.js"></script>

Versions & license notes

  • dexie-export-import: v4.x (MIT or similar — check package)
  • Marked: v4.x / v18.x builds included (BSD/MIT — check specific distribution)
  • DOMPurify: v3.x (MIT)

Always check each project's license and attribution requirements before publishing aggregated bundles.

Troubleshooting & tips

  • If parsed HTML renders oddly, verify which Marked build you have (API differences exist between major versions).
  • When upgrading Dexie, double-check DB versioning rules (schema upgrades require a migration plan).
  • Only call DOMPurify.sanitize on trusted insertion points — sanitization settings can be tuned for allowed tags/attributes.
  • If you see duplicate globals (e.g., two different Marked builds), remove the unused file and rebuild bundle.js.
